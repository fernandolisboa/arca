# Arca

The domain language of Arca, an immigration consultancy in an app for one family. One English term in code and docs, one pt-BR label in the interface.

## Language

This repo keeps its glossary as a table, not the `**Term**:` list of the `domain-modeling` skill's format: add a row before using a new domain term, with its pt-BR label, and list words to avoid in the meaning cell when a synonym tempts. A term that no screen shows says "Internal, no UI label" in the label column.

| Term (code and docs) | pt-BR UI label | Meaning |
| --- | --- | --- |
| Case | Caso | Everything Arca knows about one family: people, relationships, assets, aspirations, plan |
| Person | Pessoa | An individual in a case |
| Relationship | Vínculo | A typed link between two people (spouse, ex-spouse, partner, parent, child, sibling, in-law); stored as spouse, partner and parent edges, the rest derived |
| Unit | Unidade | The group that moves together under one route: a principal applicant plus the dependents that route covers. Computed per route |
| Principal applicant | Requerente principal | The person whose eligibility a route is evaluated on |
| Dependent | Dependente | A person covered through the principal applicant, as defined by the route |
| Native national | Internal, no UI label | Someone who has held a country's citizenship since birth: by birth, or by descent or another basis acquired on the birth date, never by naturalization, marriage or investment. Read by the fact `person.citizenshipsFromBirth` |
| Destination | Destino | A country a person accepts moving to |
| Route | Rota | A legal pathway to live in a country (a visa, residence permit or citizenship path) |
| Route version | Versão da rota | An immutable snapshot of a route's rules, with its sources, effective date and pinned country sets and official-domain lists |
| Rule | Regra | The requirements, assessments, dependents, costs, durations and documents of one route version |
| Ancestor | Ascendente | A parent, grandparent or earlier forebear of the principal, whether or not in the case; read in descent rules |
| Lineage | Linha de ascendência | The chain of people from an ancestor down to the principal |
| Rule summary | Resumo feito pelo Arca | A model's plain-text reading of one route version for an admin, with points to check; an aid to review that never decides and never reaches members; stored once per content, prompt and model, and shared by admins |
| Occupation | Ocupação | What a person does for a living, as an ISCO-08 unit group code ([ADR-0036](docs/adr/0036-case-records-and-classifications.md)); avoid "profession" and "job title" for the code |
| Work period | Trabalho | A stretch of work by one person: employer and workplace country, relation (employee, contractor, self-employed, owner), occupation, capacity, full time, start and end or ongoing, and an optional display label that stays with the profile ([ADR-0036](docs/adr/0036-case-records-and-classifications.md)); avoid "job" and "employment" for the record |
| Record collection | Internal, no UI label | A person's own list of records (work periods first) that rules read item by item, with `covers` for the time the items span; distinct from comparison Coverage |
| Qualification | Formação | A degree or diploma a person holds, coded by ISCED-F 2013 field of study (#511); avoid "degree" for the record |
| Professional registration | Registro profissional | A person's licence to practise a regulated occupation with a body in one country, such as a medical council (#511); avoid "license" |
| Residence period | Período de residência | A stretch of lawful residence by one person in one country, with its basis and dates (#513); avoid "stay" |
| Field of study | Área de formação | What a qualification was in, as an ISCED-F 2013 four-digit code ([ADR-0036](docs/adr/0036-case-records-and-classifications.md)); `studyFields` and `study-fields` in code; avoid "course" and "major" |
| Classification | Internal, no UI label | A numbered, sourced file of the codes of one official list, occupations or fields of study, that a route version pins so its requirements can name codes ([ADR-0036](docs/adr/0036-case-records-and-classifications.md)) |
| Rule case | Caso de teste da regra | One table-driven test entry for a route version, in its cases file; not a family's case |
| Official-domain list | Lista de sites oficiais | A versioned list of hosts that count as official for a country or international body |
| Evaluation | Avaliação | The result of applying a route version to a person or unit |
| Prompt cache | Internal, no UI label | The model vendor's short-lived store of a request's opening bytes, which a later request that opens with the same bytes reads at a fraction of the input price. Arca marks only a call's instructions for it ([ADR-0004](docs/adr/0004-ai-providers-behind-ports.md)); a cache read and a cache write are the input tokens a call took from it and put into it |
| Evaluation engine | Internal, no UI label | The pure functions in `packages/domain` that select a version, compute the unit and evaluate requirements |
| Case snapshot | Internal, no UI label | The engine's structured, free-text-free view of a case at one moment (`CaseSnapshot`) |
| Completeness marker | Internal, no UI label | A person's flag that their spouses, partners, children or parents are all recorded; without it, unrecorded people may exist |
| Aspiration | Anseio | What a person wants, accepts, refuses and prioritizes |
| Deal-breaker | Inegociável | A condition that rules a route or destination out for a person |
| Execution mode | Modo de execução | How a step is presented: self-service, guided, delegated or family |
| Self-service | Autoatendimento | The person completes the step directly, usually via a prefilled link |
| Guided | Guiado | The app walks the person through the step and checks each stage |
| Delegated | Delegado | The step goes to a professional or partner, with the case summary ready |
| Family (mode) | Em família | The step is assigned to a relative in the case who offered to help |
| Action point | Ponto de ação | Where a step actually happens: link, phone, office, partner; says whether the step can be done online |
| Family area | Área da família | The screen with the people in a case, who has an account, invites and who may upload documents for whom; grants no access by itself |
| Guided questions | Perguntas guiadas | The step-by-step questions per person that fill the case, each setting one part of it (a fact, a completeness marker, dependence, an asset or a relationship's details); "Não sei" leaves it unknown |
| Free-text intake | Contar com suas palavras | Filling the case from the member's own description of the family, through an intake draft the member reviews (spec 0008) |
| Intake draft | Rascunho | The answers proposed from a member's own description of the family, which the member reviews person by person and fact by fact before anything is saved (spec 0008); the text itself is never stored |
| Playback | Resumo do caso | The case read back in plain sentences, each linked to the question that sets it, so the person can correct it |
| Keeper | Quem cuida dos dados | The one account that writes a person's facts and decides who sees them: the person, or whoever added someone without an account; not the data-protection controller |
| Case member | Participante do caso | An account in a case; it sees the case's people and relationships, and keeps the people it added |
| In the planning | Entra no planejamento | A person of the case the routes are evaluated for (`caseMember` in the code); a relative outside it, such as a grandparent who stays, is only described |
| Asset | Bem | Something of value owned by one or more people of the case, with each owner's share; a co-owner named by another keeper stays pending until their keeper confirms |
| Profile share | Compartilhamento de dados | A keeper letting a chosen member see a person's profile or, separately, their finances; not a document share |
| Case stage | Etapa do caso | Where a case stands on the home: telling about the family, the guided questions, then the routes; counted in the client from the case and its answers, never an eligibility decision |
| Progress | Progresso | Documents obtained and steps done out of what a person's or the family's chosen routes need, computed in code; unknowns shown apart |
| Shared analysis | Análise compartilhada | A comparison or recommendation an adult shares, read-only and revocable, with chosen people in the case; not a document share |
| Destination comparison | Comparar destinos | One adult's ranking of the countries that have a route, by criteria they weigh themselves; computed in code, private to that adult unless shared as a shared analysis ([ADR-0026](docs/adr/0026-destination-comparison-data.md)) |
| Criterion | Critério | One thing a destination comparison scores, such as safety or climate; knowledge data with a stable ID, scored from a country indicator or from the person's own rating, or a suggested rating while they have none |
| Personal criterion | Critério pessoal | A criterion of a comparison version that each adult scores with their own rating, or a suggested rating until they give one, such as climate; knowledge data, unlike an own criterion. Avoid "subjective criterion" |
| Own criterion | Critério próprio | A criterion an adult creates and names for their own comparison, scored from their rating, or a suggested rating when its name matches a ready suggestion; case data, unlike a personal criterion. Avoid "custom criterion" |
| Suggested criterion | Sugestão | A criterion the comparison screen proposes, from a ready list or from Arca's model, with a starting weight; becomes an own criterion when the adult adds it, or stays out of the suggestions when they turn it down ([ADR-0034](docs/adr/0034-criterion-suggestions.md)) |
| Cost total | Total em dinheiro | What a route version's costs add up to for one principal, per currency, split into what certainly applies and what may on top; computed by the engine, never by a model. Durations are not summed |
| Rule text | (no UI label) | A route version title, or a document note, in the screen's language, paired with the English the version writes, kept in the repository beside the versions; never part of a version or its hash ([ADR-0037](docs/adr/0037-rule-texts-in-the-screens-language.md)) |
| Suggested rating | Sugestão do Arca | Stars from 1 to 5 the comparison suggests for a country on a personal or own criterion, from a public source in the repository; they score the criterion until the adult rates it, and the adult's own stars always win ([ADR-0035](docs/adr/0035-suggested-ratings.md)) |
| Suggestion key | (no UI label) | The ID a suggested rating is filed under: a personal criterion's ID or a ready suggestion's ID; an own criterion takes the key whose catalog name it matches ([ADR-0035](docs/adr/0035-suggested-ratings.md)) |
| Document checklist | Lista de documentos | The per-person list of the documents one route asks for, computed in code from the route version and the case: one list per person in the unit, plus the items the unit hands in once ([#519](https://github.com/fernandolisboa/arca/issues/519)) |
| Document item | Documento exigido | One entry of a route version's document list, with who hands it in, an optional condition and its sources. Apostille, translation and validity appear only where a source states them; absent means Arca does not know, never "not needed". A version with no list means Arca does not know the route's documents yet; an empty list means the route asks for none |
| Document kind | Tipo de documento | An open lowercase tag naming what a document is, such as `birth_certificate`; route items and guide entries share it |
| Document guide | Onde tirar | Reviewed data, with official sources, on how to get each document kind in one issuing country: office, cost, lead time, online link and how its apostille is obtained; no activation ([ADR-0039](docs/adr/0039-document-guides.md)) |
| Checklist mark | Marcação | A keeper's had or missing on one document item for one person, with an optional linked vault document |
| Departure checklist | Saída do país | What to do when leaving a country, and the documents that trace where the family's money came from, each item with official sources and the date they were read; reviewed data, the same for every account ([ADR-0038](docs/adr/0038-departure-checklists.md)) |
| Weight | Peso | How much a criterion counts in one adult's comparison, from 0 (left out) to 5 |
| Rating | Sua nota | The one to five stars an adult gives a country on a personal criterion or an own criterion |
| Score | Nota | A country's result on one criterion, from 0 to 10, computed in code; unknown when the value, or both the rating and any suggested rating, are missing, never zero |
| Total score | Nota final | The weighted mean of a country's known scores, from 0 to 10 |
| Coverage | Dados conhecidos | The share of an adult's weight that a country's known scores carry, suggested ratings included; under half puts the country in "Poucos dados" |
| Few data | Poucos dados | The group of countries with less than half of an adult's weight known, listed after the ranked ones without a rank |
| Hidden country | País oculto | A country an adult left out of their comparison; still scored, listed last without a rank, and brought back with one tap; dropped on the next write once no route covers it |
| Country indicator | Indicador do país | A versioned, sourced knowledge file with one measured value per country, such as the homicide rate, with its year |
| Comparison version | Versão dos dados de comparação | A versioned knowledge file with the criteria and the country indicators they read; activated or rejected as a whole, like a route version |
| Guided tour | Tour guiado | The first-run walkthrough of the app and the hint shown the first time a screen opens; skippable and replayable |
| Fact | Dado | A typed value about a person or unit that rules read, such as an age at a date; derived from the case in code |
| Requirement | Requisito | A condition of a route version, evaluated as true, false or unknown, with a source |
| Assessment | Critério subjetivo | A judgment factor of a route version, such as national importance; shown with its evidence, never as pass or fail |
| Country set | Grupo de países | A versioned, sourced list of countries a rule refers to, such as treaty countries |
| Proposed version | Versão proposta | A route version in the knowledge catalog that is neither active nor rejected |
| Decision state | Internal, no UI label | Per version identity (route, number, content hash; or comparison, number, content hash, under a key no route can take): active, rejected or proposed. A version with no counted decision is proposed |
| Superseded version | Versão substituída | A version that selection does not pick: at a given date, because a correction or a later version takes it (spec 0002); on the activation screen, at every date from today on, while the versions that take its place are not rejected. A proposed one needs no decision; the activation screen lists superseded versions under Anteriores, with rejected ones |
| Newer proposed version | Nova versão proposta | A version not yet active that selection would pick, at the evaluation date or later, instead of the version evaluated |
| Correction | Correção | A route version that fixes a data error in an earlier one, named by its `corrects` field; once in effect, the version it fixes is no longer selected |
| Official source | Fonte oficial | A source on a host the knowledge base lists as official for a country or an international body |
| Secondary source | Fonte secundária | A non-official source cited beside an official one, never instead of it |
| Stale source | Fonte desatualizada | A source not re-verified in the last 90 days; evaluations that cite it say the rule needs re-checking |
| Activation | Ativação | An admin's approval of one route version or comparison version, bound to its content hash, with a passkey step-up again since [ADR-0031](docs/adr/0031-rule-updates-on-request.md); counts once stored ([ADR-0027](docs/adr/0027-admins-and-the-checked-batch-activation.md) decisions took none; earlier ones carry a step-up, [ADR-0022](docs/adr/0022-single-approver-activation.md)). A session review's activation has no admin and no passkey: its migration stores it ([ADR-0032](docs/adr/0032-session-reviews-activate-through-a-reviewed-pull-request.md)) |
| Rejection | Recusa | An admin's decision that a version, proposed or active, will never be used; once it counts, selection skips it |
| Admin | Administrador | An account that may activate or reject knowledge-base versions and give or take away the admin role; on the owner list, or holding an admin grant another admin gave from the family area. Replaces "approver" |
| Decision | Decisão | An admin's activation or rejection, stored with its author, or a session review's activation, stored by its migration with none; decisions made before ADR-0027, and since ADR-0031, also keep the step-up they consumed |
| Step-up | Confirmação com chave de acesso | A fresh passkey verification for one sensitive action, bound to that action |
| Content hash | Código do conteúdo | SHA-256 of the canonical JSON of a version and every file it pins; what a decision is bound to |
| Passkey | Chave de acesso | The WebAuthn credential a person signs in and confirms sensitive actions with |
| Knowledge catalog | Internal, no UI label | The validated, hashed route versions, country sets and official-domain lists, held as insert-only rows in the `knowledge` schema and re-hashed on read ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)); not the pnpm catalog of dependency versions |
| Admin grant | Internal, no UI label | An insert-only record that an admin gave the admin role to a confirmed account sharing a case with them (with a step-up), or took it away |
| Owner list | Internal, no UI label | The reviewed file in the repository that names, by account ID and per environment, the accounts that are always admins and cannot lose the role in the app; formerly the approver list |
| Activation screen | Tela de ativação | Where an admin reviews a proposed version as data, with an update request's proposal lists apart, and activates or rejects it |
| Independent check | Verificação independente | The model's report that compares a proposed route version, item by item, with the official sources it cites: matches, differs or could not be checked, an item resting on up to five quotes, each quote and value checked in code against the text fetched for its page; never activates a version by itself and is never part of the content hash. Replaced by update requests ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)) and removed with the old loop ([#463](https://github.com/fernandolisboa/arca/issues/463)); its rows stay read-only as history |
| Text layer | Internal, no UI label | The text a PDF's pages carry beneath what they draw, which an update request's quote check reads through pdf.js; a scanned PDF has none ([ADR-0028](docs/adr/0028-pdf-text-in-the-independent-check.md)) |
| Rule audit | Auditoria de regras | An authoring session's review of one route against the law, not only its cited pages: it re-reads the official sources whole, looks for later amendments, follows leads from other sites and looks for what the rule leaves out; only an official source changes a rule; it ends in a correction, a new version or a record of no change, and leaves a dated record in the route notes ([runbook](docs/runbooks/rule-audit.md)); avoid "independent check", the retired model report at activation. Ends once rules move to the database: rules then change only through update requests ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)) |
| Monthly run | Internal, no UI label | The rule audit a scheduled task starts each month: a set number of routes, those audited longest ago first, with no person watching, so it writes and merges less than an audit the owner asks for ([the monthly run](https://github.com/fernandolisboa/arca/blob/fc269c37e9f7dd1c179153c14eb72859dc685619/docs/runbooks/rule-audit.md#the-monthly-run)). Replaced by update requests ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)) and removed with the old loop ([#463](https://github.com/fernandolisboa/arca/issues/463)) |
| Route notes | Internal, no UI label | A route's file of dated audit records, newest first, which the next audit of the route reads back ([the audit record](docs/runbooks/rule-audit.md#the-audit-record)); public law only |
| Checked version | Conferida pelo Arca | A proposed route version whose current independent check report is clean: every item matches, with each quote and value checked in code; its one-tap activation was removed by [#460](https://github.com/fernandolisboa/arca/issues/460). Replaced by update requests ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)) and removed with the old loop ([#463](https://github.com/fernandolisboa/arca/issues/463)) |
| Flagged version | Conferida em parte | A proposed route version whose current check report is not clean: an item differs or could not be checked; decided one by one. The proposed list labels it "Difere" when an item differs and "Confira" when items only could not be checked (beside "Tudo bate" for a checked version and "Na fila" for one with no current report). Replaced by update requests ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)) and removed with the old loop ([#463](https://github.com/fernandolisboa/arca/issues/463)) |
| Check point | Ponto conferido | One item of a check report, shown under the rule item it is about: bate (matches), difere (differs) or não conferido (could not be checked). A review step takes the tone of its worst point. Replaced by update requests ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)) and removed with the old loop ([#463](https://github.com/fernandolisboa/arca/issues/463)) |
| Stale check | Verificação vencida | A route version whose reports no longer count: its content, country guide, prompt or model changed, or the newest report outlived its 30 days (one day after a failure); an admin checks it again with "Analisar com o Arca" or "Analisar as versões da fila"; nothing checks it again by itself. Replaced by update requests ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)) and removed with the old loop ([#463](https://github.com/fernandolisboa/arca/issues/463)) |
| Check start | Internal, no UI label | A recorded start of one route version's independent check, made by an admin tapping "Analisar com o Arca" or "Analisar as versões da fila"; an admin's starts have no cap; never two live for one version; dead after 30 minutes with no report. Replaced by update requests ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)) and removed with the old loop ([#463](https://github.com/fernandolisboa/arca/issues/463)); its rows stay read-only as history |
| Check progress | Análise do Arca | What a running independent check recorded as it went, shown on its own screen: the stage, each cited page as it is read with its outcome, the passages being picked, the comparison and what its model calls cost so far; counts, official URLs, model names, token counts and fixed codes only, never page text or anything the model wrote. Replaced by update requests ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)) and removed with the old loop ([#463](https://github.com/fernandolisboa/arca/issues/463)); its rows stay read-only as history |
| Fetch log | Internal, no UI label | A check report's record of each cited URL: read or the fixed failure code, final status, time, SHA-256 of the text sent, whether it was cut, the machine-readable address read in the page's place, if any, and whether the text came from a copy attached to a correction request because the page could not be read. Written only by the retired independent check ([#463](https://github.com/fernandolisboa/arca/issues/463)); its reports stay read-only as history |
| Machine-readable address | Internal, no UI label | An official source's optional `machineReadableUrl`: an address on a pinned official host that serves the same official text as data (JSON, XML or a print form), which an update request's quote check reads in place of the page; the activation screen shows the address under the page's URL |
| Echo rule | Internal, no UI label | The quote check's refusal of a quote on a page whose own address, any URL of the chain requested for it, states the item's value or makes up the quote: such a page may only be repeating what it was asked ([ADR-0027](docs/adr/0027-admins-and-the-checked-batch-activation.md)) |
| Years reading | Internal, no UI label | The second way a quote may state a count of months that makes whole years other than 0 or 1: as those years right before a word for years, so `P60M` is stated by "5 years" or 五年 but not by "article 5". The echo rule reads it only when the quote relies on it (`wholeYears` on a check value; [ADR-0027](docs/adr/0027-admins-and-the-checked-batch-activation.md#amendment-2026-11-20-a-count-of-months-stated-as-whole-years)) |
| Scripted checker | Internal, no UI label | The `RuleChecker` that development, previews, tests and e2e use until a model is configured; its reports are stored under the model `fake` and are never clean. Replaced by update requests ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)) and removed with the old loop ([#463](https://github.com/fernandolisboa/arca/issues/463)) |
| Passage locator | Internal, no UI label | The step of the independent check that picks, from the outline of a cited page too long to send whole, the passages the check then reads for each item; a fast model in production, a scripted one that picks nothing elsewhere; it only chooses among verbatim passages of the page. Replaced by update requests ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)) and removed with the old loop ([#463](https://github.com/fernandolisboa/arca/issues/463)) |
| Catalog check | Internal, no UI label | The manual run of the independent check on the newest version of every bundled route against its live official pages, which reports what matched and why the rest did not; it measures a change to the check and never gates one. Replaced by update requests ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)) and removed with the old loop ([#463](https://github.com/fernandolisboa/arca/issues/463)) |
| Country guide | Internal, no UI label | The reviewed, versioned data file per country that the independent check loads, its per-country specialist: governing laws, how they change, known pitfalls; never a source and never a list of official hosts; lands in its own pull request; not a Claude Code skill. Replaced by update requests ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)) and removed with the old loop ([#463](https://github.com/fernandolisboa/arca/issues/463)) |
| Rule report | Aviso de regra errada | A person's flag that a rule they were shown may be wrong; opens a research task. The button reads "Avisar regra errada" |
| Update request | Pedido de atualização | A request to refresh one route, or to add a route for one country by naming its visa or entry type; filed by an admin, or by a member from the results and then released or declined by an admin (the member sees Recebido, Liberado, Concluído or Recusado; the admin's list reads "Pedidos dos participantes"); runs the update stages once and ends with a proposal or a fixed failure code; its note and file never reach a model; one live request per route, or per country for a new route; replaces the correction request ([ADR-0031](docs/adr/0031-rule-updates-on-request.md)). The button reads "Pedir atualização", and for a new route "Pedir rota nova ao Arca"; one with no end an hour after it was asked for is stalled (Parou no meio) and blocks nothing |
| Session review | Revisão em sessão | A Claude Code session the owner asks for that checks one country's stored routes against the official sources and stores the corrected versions, already active, through a reviewed pull request; at most three rounds of adversarial review a route, and what stays disputed is listed for the owner ([ADR-0032](docs/adr/0032-session-reviews-activate-through-a-reviewed-pull-request.md)) |
| Update stage | Etapa da atualização | One step of an update request, in this order: research (Pesquisa), validation (Validação), at most one correction round (Correção; not a correction version, though it may produce one) and a final validation (Validação final); a pure controller picks the next one, so a request ends after at most two rounds; a stage the request did not need is skipped (Não precisou), and one a failure or stall left unrun shows as Não rodou |
| Proposal | Proposta | The proposed route version an update request ends with, shown to admins as three lists: confirmed items (Confirmados), divergent items with the reason (Divergentes) and items nobody could confirm, with their official links (Não confirmados); the last list is information, never a reason for another round |
| AI provider key | Chave de API | An AI provider's API key (Anthropic or TypeSafe) stored encrypted in AI settings; shown only as set, with its last four characters and date ([ADR-0031](docs/adr/0031-rule-updates-on-request.md#typesafe-jev-validates-amendment-2026-11-16)) |
| Effort | Esforço | How hard a Claude model works on an update stage (low to max), chosen per stage in AI settings; the reviewed default is Padrão |
| Validation answer | Internal, no UI label | The validator's verdict on one item with its quote verified in code: supports, does not support or cannot tell, with a short reason |
| Edit item | Editar item | An admin's hand fix of one item of a proposal, with its source and quote, which writes a new proposed version that corrects it after the same checks in code |
| Rule import | Internal, no UI label | The one-time, idempotent data migration that loads every bundled route version, country set and official-domain list into the database with its hash, refusing a hash mismatch; it writes no decision, so states stay computed from stored decisions |
| AI settings | Configurações › IA | The admin-only settings for model calls: the Anthropic and TypeSafe API keys (stored encrypted, shown only as set with their last four characters), the model and effort per update stage, the source-change notice switch and day, and what each request cost |
| Source-change notice | Aviso de mudança na fonte | The optional weekly job, off by default, that hashes the official pages active versions cite and tells admins which routes' sources changed; never calls a model or starts a request |
| Correction request | Pedido de correção | An owner-list admin's note that an item of a version (or the whole version) is wrong, with sources as leads: links, pasted text or files, a file naming the cited page it may copy ([ADR-0029](docs/adr/0029-correction-requests-and-the-corrector-session.md)).
