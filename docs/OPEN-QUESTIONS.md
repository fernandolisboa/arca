- [ ] Most items the independent check can read still come out could not be checked, because a match needs one passage that carries the whole item and many bundled items join several provisions in one title (a threshold, a sponsor grade and an occupation level; a spouse rule with its exception). Measured 2026-11-09 by the catalog check: 17 of 158 items match, 91 were read and not confirmed, 44 had no page read. Two ways to raise it, each a change to the check that needs its evaluation: let a match rest on up to a few quotes, each verified, or write items with one provision each. The first landed with [#354](https://github.com/fernandolisboa/arca/issues/354) on 2026-11-10: 28 of 162 items match, 17 of them on several quotes, and 89 are still read and not confirmed; the rule audits (#355 to #360) write one provision per item. The leap-day item is a convention most laws never state, so it rarely matches anywhere. Since 2026-11-11 a version leaves it `unsettled` where no official text settles it, and every audit runs [the check loop](runbooks/rule-audit.md#the-check-loop), which fixes the rule, its sources or the item until the check confirms it, and records each item left as `unreadable`, `checker-gap` or `differs-open`.
- [ ] A `checker-gap` cause the audit of 2026-11-11 met on `cz-eu-blue-card` and `dk-pay-limit` ([Czech record](research/routes/cz-eu-blue-card.md)): a law served only as one long machine-readable answer with no headings (the Czech fees act on the e-Sbírka fragment API, the LexDania XML of the Danish Aliens Act) is cut before the provision an item cites, and the passage locator has no outline to pick from. A reader for the fragment API that follows a source's anchor, and locating passages by the provision number in a source's title, would let the check reach both.
- [ ] Two `checker-gap` causes the check loop met on `us-eb5` on 2026-11-11 ([record](research/routes/us-eb5.md)): the code that confirms an item's value inside a quote looks for figures, so a value the law writes in words ("twenty-one", "two years", "second anniversary") is never confirmed; and on a very long page the passage locator does not pick the same passages each run, so an item can match in one run and not the next (`capital`, `engagement`). Reading number words in a language-neutral way, and a locator that ranks a page's passages the same way each run, are each a change to the check that needs its evaluation. The Mercosur audit of 2026-11-11 ([#358](https://github.com/fernandolisboa/arca/issues/358)) met three more: an item that is possible only because a law does not name a person (a spouse's children) can never match, since no quote shows an absence, so every version with one is always flagged; an item whose list of states comes from an agreement's opening and its family article, two passages the model will not join; and pages the reader cuts (Argentina's Civil and Commercial Code) or the passage locator does not reach (article 4 of Paraguay's Ley N.º 6984). The audit of the British, Irish, Australian and Japanese routes on 2026-11-11 ([#359](https://github.com/fernandolisboa/arca/issues/359)) met three more: amounts written with a space between thousands (AUD "$6 135" on legislation.gov.au) and Japanese numerals written in kanji (五年, 六月) are not confirmed as values; the Migration Regulations 1994 compilation document, 1.2 million characters, reaches the model only as its table of contents, so no item on it is checked; and e-Gov's whole-law XML for the Immigration Control Act and the Civil Code reaches it only as the law's opening.
