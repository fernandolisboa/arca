## Context

The owner asked on 2026-11-07 why activating a rule asks for a passkey again, and chose, on three decision cards:

1. **An admin role in the app**, given and taken away by an admin, instead of a list of approvers in the repository.
2. **No step-up on a decision**: a signed-in admin activates or rejects with one tap.
3. **An AI analyst checks each rule against its own official sources**, and an admin activates the rules it finds clean together, with one tap; flagged rules are decided one by one.

Facts behind those choices:

- The step-up proves that a person, not an agent holding the owner's GitHub token, made the decision (ADR-0014). Signing in already takes a passkey, and no agent holds an app session, so a signed-in admin proves the same thing against that attacker.
- ADR-0022 already accepts that whoever writes the production database as `app_auth` or the owner role can forge a decision.
- The 24 route versions seeded so far wait for activation, one passkey prompt each. The owner trusts a careful model check over his own reading for this kind of repetitive comparison, and wants his attention only where the check fails.
- The independent check was specified in ADR-0014 and never built, for lack of an API budget. The owner's Ultra plan now pays for direct API calls ([ADR-0023](0023-free-text-intake-sends-the-writers-own-words.md)).
- No Claude skill covers immigration law per country (checked 2026-11-03). ADR-0014's country guide is the per-country specialist: one check loads the guide of the version's country.

## Decision

### Admins

- An **admin** may activate and reject knowledge-base versions, ask for rule summaries, read rule reports, and give or take away the admin role. The role is global, never per case, and grants no access to any case's data.
- The **owner list** in the repository (today's approver list, renamed, with the same account IDs) names the accounts that are always admins, per environment. It changes only by a reviewed pull request, and an owner-list admin cannot lose the role in the app. It is how the first admin exists.
- Any other admin holds an **admin grant**. The grant history is insert-only: one row when the role is given and one when it is taken away, each with both account IDs and a time the database sets after the lock below. Rows are kept for as long as the decisions that rely on them, so they are retained, with account IDs only, like decisions.
- An admin gives the role, from the family area, to a confirmed account that shares a case with them, and takes it away the same way. Any admin, owner-list or granted, can take away the grant of a member of a case they share, which is accepted; a grant held by someone who shares no case with an admin cannot be taken away in the app (#328).
- **Giving the role needs a step-up** of a new purpose, `admin_grant`, with the action `grantAdmin` bound to the grantee's account ID and the client's action nonce, under the step-up's usual guarantees (spec 0003 R5). The grant row records the step-up it spent. Taking the role away needs none.
- Each change writes an audit event and sends the owner-list admins a security notice with a generic text and a link, no names, so an unexpected grant gets noticed.
- The API reads the role from the database on every request and never caches it in the session, so taking it away takes effect at once.

### Decisions without a step-up

- A signed-in admin activates or rejects a route version or a comparison version with one request.
- **Who writes what:** only `app_auth` inserts decisions and admin grants. Before its transaction, the API checks on `app_api`, under row-level security, that a grantee is confirmed and shares a case with the admin; the small race between the two transactions is accepted. The `app_auth` transaction sets the request's account as its identity, takes transaction advisory locks keyed by the accounts involved, in a fixed order (the author for a decision; the granting admin and the grantee for a grant or a removal), checks the role, and inserts. `app_auth` reads admin grants, decisions and check reports for that; `app_api` only reads decisions and grants.
- The decision's insert policy requires the author to be the transaction's own account and the proof to be `session`, and the database sets the row's time with `clock_timestamp()` after the lock, as it does for grant rows. The row also records why its author was an admin: the owner list, or the grant row in force. A database check keeps the proof and the step-up fields consistent: a `step_up` row has every assertion field, a `session` row has none.
- **When a `session` row counts:** when the reason it records holds: its author was on the owner list when it was stored, or the grant it names was in force at the row's time, by the grant history. A grant row counts the same way only when its granting admin was an admin at its time. So a decision keeps counting after its author loses the role, and a grant row by an account that was never an admin, by the grant history, counts for nothing, a rejection included. The owner list keeps no history, so an `owner_list` row counts by the basis it records, which `app_auth` checked against the list when it stored the row; leaving the list then never undoes a decision, and losing the role never revives a version its author rejected. Owner-list account IDs are public in the repository, so checking today's list would stop no forger, who already needs an `app_auth` write (#326).
- Rows stored under ADR-0022 keep their step-up and are re-verified exactly as before, against the owner list; their rejections still count even when they do not verify. The purpose `knowledge_decision` stays in the contract, the database check and the re-verification; only the step-up options route stops offering it. The subject kind of a comparison decision (ADR-0026) lives on the row.
- The decision routes keep the API's same-origin check on every state-changing request (the `Origin` header or `Sec-Fetch-Site`), and the client keeps the strict content security policy with Trusted Types and `frame-ancestors 'none'` (spec 0001), so another site cannot make an admin's browser decide, frame the one-tap button or run script on the screen that shows page quotes.
- A forged `session` activation counts if its author was an admin at the row's time; that needs a write as `app_auth` or the owner role, the attacker ADR-0022 already accepts.

### The independent check

It is ADR-0014's check, now built, with these choices.

**Scope and items**

- Route versions only. A comparison version's values come from a statistics API, not from law text, so it is decided on its own.
- The items are every requirement, assessment, dependent rule, cost and duration, the leap-day rule and the closure when the version has them, and each pinned country set's members, checked against the set's own sources on the set's own pinned lists. A pure function in `packages/domain` lists them by stable key. A version with sourced content that function does not list is never clean.
- Settings that cite no source (effective dates, currency, reference dates) are not items; the report panel says the check does not cover them.

**Starting and storing**

- When the activation screen opens (and, since the on-demand amendment below, when an admin asks for one version), it sends a same-origin `POST`, for admins only, that starts a check for each proposed, not rejected route version with no current report and no recent start. Since 2026-11-11 the screen-opening start also skips a superseded one, which selection picks on no date from today on ([CONTEXT](../../CONTEXT.md)), so the daily starts go to versions that can be used; it is due again if the version that replaced it is rejected. Listing versions has no side effect.
- A start ledger records each start (an ID, route ID, number, time), written and read by `app_api` under an environment-wide advisory lock, so concurrent screens neither exceed 20 starts in any 24 hours per environment nor start a version twice. (Changed 2026-11-12: only automatic starts are capped, at 15; see the on-demand amendment.) A start older than 30 minutes with no report is dead. Starts are kept, with no personal data.
- A Vercel Workflow in São Paulo runs one step with no step retries, whose input is the start ID, route ID and version number only, and no account ID: the step reads only public rule data and writes only the unowned report table (and, since the on-demand amendment below, the unowned progress table), an exception to spec 0004 R9's identity-bound `app_jobs` steps; the route ID and number join the workflow arguments' closed kinds ([ADR-0009](0009-background-jobs-guarantees.md)). The step runs as `app_jobs`: it fetches, calls the model, checks the answer and inserts the report keyed by its start, turning every error into a fixed code. No page text or model output becomes a step input or output.
- A report records the start, route ID, version number, content hash, guide hash (the value `none` without a guide), prompt version, model, time, items and fetch log (URL, final status, time, SHA-256 of the text sent, whether it was cut and, since the machine-readable address amendment below, the address read in the page's place). It is public rule data with no account, unowned in the personal-data registry; `app_jobs` inserts and reads, `app_api` and `app_auth` only read, and nobody updates or deletes.
- A version's **current** report is its newest report whose content hash, guide hash, prompt version and model match today's, if it is less than 30 days old, or less than one day old when a fetch or the model call failed or no page text was sent (since the 2026-11-09 amendment below, also when a long page had no passage picked); after that the next screen opening checks it again. The country's current guide is its highest version in the bundled catalog.

**Fetching**

- For each item, only the `official` sources that item cites (or, since the machine-readable address amendment below, the address those sources name in a page's place), over `https`, on a host of one of the pinned official-domain lists that cover it; every redirect hop (at most three) must stay on those hosts; only a final `2xx` response counts.
- `node:https` with a `lookup` that asks for every address, keeps only globally reachable unicast ones by the IANA special-purpose registries (so loopback, private, link-local, unique-local, CGNAT, unspecified, multicast, reserved, metadata, and IPv4-mapped, IPv4-compatible, NAT64, 6to4 and Teredo forms are refused) and connects to one checked address while verifying the certificate against the host name. No new HTTP client.
- No cookies or credentials; limits on bytes received, decompressed size, time and redirects; each page's text is capped at a size that holds a whole code (3,000,000 characters since the long-page amendment below; 60,000 before it, which cut most laws).
- HTML becomes plain text through one maintained HTML-to-text library, the only dependency this ADR adds: a pure parser with no browser DOM emulation and no script execution, no network, no install scripts, a permissive license and the repository's minimum release age, for it and every package it pulls in, named in its ticket under the supply-chain review. The conversion drops `script`, `style`, `noscript`, `template`, comments, and elements marked `hidden`, `aria-hidden` or hidden by an inline style, and, since the long-page amendment below, struck-through text; text hidden by a style sheet is left to the value check below. The library is parse5 (MIT; its one dependency, entities, is BSD-2-Clause), whose tree Arca walks without recursion ([#329](https://github.com/fernandolisboa/arca/issues/329)).
- A PDF, another content type, a page with no text of its own (one that scripts draw, `no_text`) or a failed fetch makes the items that rely on it **could not be checked**; JSON and XML answers are read since the machine-readable address amendment below, and a PDF's text layer since [ADR-0028](0028-pdf-text-in-the-independent-check.md).

**What the model reads and answers**

- The version as the admin's activation view lays it out (no hash, no state, no rule cases), the item keys, each page's text in its own delimited data block with its URL and angle brackets replaced, as in ADR-0025, and the country guide in its own data block after the pages. The prompt says the pages are the authority and a guide never outweighs them. The instructions come first so they can be cached. No case data, so no exception to minimization.
- A closed schema with one entry per item key: a status (**matches**, **differs** or **could not be checked**) and, except for the last, a quote and its URL (since the several-quotes amendment below, one to three quotes, each with its URL). A **differs** entry carries one short plain-text note on what differs, and, since the long-page amendment below, a **could not be checked** entry carries one saying why; these are the only free text, because a flagged item is what a person reads next. Code strips URLs and host names from a note and caps its length, and drops the note of any answer it refuses itself. Unknown or duplicate keys are dropped. No recommendation, no verdict on the rule.

**Checked in code**, in pure functions in `packages/domain`. A quote counts only when (since the several-quotes amendment below, every quote of an item, which may rest on up to three):

- it is a verbatim substring, after whitespace is normalized, of the exact text sent to the model for a URL that the item itself cites, and, on an excerpt, lies within one run of it;
- its length is within a minimum and a maximum;
- it contains no decoded query value of four characters or more from any URL of the redirect chain, and the item's value does not appear as a whole token in any of those URLs, so a page that echoes its own address cannot be quoted;
- for an item that states a number, an amount, a date, an age or a duration, the item's value, normalized for separators, decimal commas, currency and unit, appears in it (since the several-quotes amendment below, in at least one of the item's quotes). The model picks the passage; code compares the value.

A quote that fails, a missing item, an item that cites no official page or none of whose pages was read, and a match from a page cut by the size cap are **could not be checked**. A report is **clean** when it has at least one item and every item matches; a report written by the scripted checker used outside production is never clean.

**Model, cost and display**

- A `RuleChecker` port with a Claude adapter on the shared call shape (no tools, no SDK retries, one retry on an unparsable answer). The model is kept in reviewed code; it starts as `claude-sonnet-5-5`, a strong model that differs from the one the authoring sessions write rules with. A check is one or two calls, plus, since the long-page amendment below, one fast-model call for each long page.
- Long laws drive the cost: an estimate of ten to fifty U.S. cents a check (2026-11-07, from the rule summary's token prices). The 20-a-day cap bounds a bad day to about ten dollars per environment (about twenty-five since the long-page amendment below; changed 2026-11-12: only automatic starts are capped, and the Anthropic Console's spend limit bounds the rest), and a version is checked once per content, guide, prompt and model every 30 days at most.
- The activation screen shows each version's status (checked, flagged, running, stale or not checked) and the report in its own panel, labelled as written by a model that can be wrong, with quotes and URLs as plain text, never links, the guide's country and version, and what the check does not cover. A stale or missing report shows as such; could not be checked never reads as passed. The report is never part of the content hash.
- **A difference opens no research task yet**: no research agent exists. The admin rejects the version or asks for a correction, written in an authoring session like any rule.

### Country guides

- One file per country and version under the knowledge data, immutable and hashed like other knowledge files: the laws and regulations that govern the country's routes (each with a URL on a pinned official-domain list), how they are usually amended, and known pitfalls. A guide never widens what counts as official and is never a source.
- A guide is a trust root: the `knowledge-immutable` check makes it land in its own pull request, as it does for official-domain lists, and it needs no activation. A check runs with no guide when the country has none, and the panel says so.

### Activating the checked versions together

- A **checked version** is a proposed route version whose current report is clean; a **flagged version** has a current report that is not clean.
- The activation screen offers one action for every checked version. The client sends the identities (route, number, content hash) it showed; the server activates only those that are still proposed, still checked under a current report and still match the bundled hash, and answers which were activated and which were skipped, with a reason code each. Each activation is its own decision row and audit event. The statuses are read once, before the decisions and outside their transactions, so a report written while a batch runs is not seen; one decision accepts the same window for a rejection stored after it read the states (#331).
- This reverses ADR-0014's rule that a report never enables or shortens the activate action, for checked versions only. Flagged versions, versions with no current report and every comparison version are decided one at a time, with no step-up either.

### Evaluation

- `apps/api/test/eval/independent-check`, run by the manual `intake-eval` workflow with a call cap, on recorded page snapshots through a fake fetcher, so runs repeat.
- Cases: ADR-0014's known-wrong versions (a changed threshold, a dropped dependent condition, an expired rule) and correct ones; ADR-0014's adversarial cases (instructions on a cited page to report a match, a quote that is not on the page, a page changed since `verifiedAt`, a redirect to a lookalike host, a guide that contradicts its source); and new ones: instructions inside the version's own text, an instruction hidden by a style sheet, a guide that steers toward a match, a page that reflects its query string, and a wrong number whose quote really is on the page.
- A run passes when no known-wrong or adversarial version comes out checked. The share of correct versions that come out checked is reported; the bar is set in the adapter's ticket.
- A change to the check's prompt, model, adapter or schema runs it and lands only after two passing runs on one commit, recorded in the real-data gate, as for the rule summary.
- As built (#330, 2026-11-07): the bar is 3 of the 4 correct cases checked. A run also fails when a wrong or adversarial case lets its target item match, gets no answer from the vendor, or writes a note a page planted; only one correct case may get no answer. The run is capped at 40 calls. A check sends at most `maxCheckPagesText` (200,000) characters of page text, pages kept whole shortest first while they fit and the rest sharing what is left, with at most 12,000 output tokens and 240 seconds a call, and makes no model call when no page was read. A call and its one retry take at most 480 seconds; the workflow function runs at the plan's maximum duration, which `@workflow/nitro` sets for its routes, so a slow check is not cut off by the platform's default. Two passing runs at `4837014` cost about US$0.01 a check (about 3,500 input and 320 output tokens), US$0.18 a run; they are recorded in the real-data gate. The guide comes after the pages in the message, as this ADR orders it. The instructions come first; no cache marker is set, since a check runs at most a few times a day and a cache entry would expire between them. (Changed 2026-11-11: the instructions are now the cached prefix of every call, as [ADR-0004](0004-ai-providers-behind-ports.md) records; a rule audit's check loop and a checked batch run many checks within the hour. The message keeps its order, so the prompt version did not change.)

### Long pages and reasons (amendment, 2026-11-09)

The first day in production left nearly every version flagged, most items at **could not be checked** with no reason a person could act on. A read of the 104 official pages the 31 bundled versions cite, made from an authoring session on 2026-11-08, showed why:

- 27 pages are longer than the 60,000-character cap, some by far (a civil code is over 1,000,000), so the check read only their opening and code refused every match on them;
- 20 pages answer markup with no text, because scripts draw them;
- 10 are PDFs, and 4 answer an access check instead of the page;
- the schema gave the model no way to say why it could not check an item.

Decided:

- **A page is read whole and a long one is sent as an excerpt.** The text cap rises to 3,000,000 characters and the markup cap to the decompressed-size limit. A page of up to 60,000 characters, the old cap, is sent whole, so no page loses the whole reading it had. A longer one is split, in pure code in `packages/domain`, into passages of whole lines that cover it end to end and start at headings, which laws in every language write as short lines; no word of any one language is looked for. A `PassageLocator` port then picks, for each item that cites the page, up to 6 passages from an outline (one line per passage: how it opens and its headings, each on one line and with no bracketed number of its own), given the items and the titles of the version's sources at that URL, which name the articles relied on. Code sends the page's opening, then every item's pick and the passage after each, as verbatim slices in page order with a gap line where text is left out, within a share of the check's 200,000 characters, equal until 2026-11-12 and since then by the items that cite each page (amendment below) and at most 60,000 a page.
- **The locator is a model, not an index.** Its Claude adapter calls `claude-haiku-5-5`, kept in reviewed code, with a closed schema of passage numbers per item key, no tools and no thinking, once per long page, with no retry, for at most 10 long pages a check. Its answer is untrusted: numbers that are not passages of the page are dropped, and all it can do is choose which verbatim passages are sent. When no passage is picked, because the locator failed, did not parse, named none of the page, was not asked, or the budget holds none, the page is sent as its opening with a gap line, marked cut, so no match counts on it and the report is short-lived. Every environment but production uses a scripted locator that picks nothing.
- **A match counts on an excerpt.** The value check is unchanged. A quote counts only within one run of the excerpt, never across a gap line. The prompt tells the model an excerpt is not the whole page: a provision missing from it is **could not be checked**, never **differs**.
- **A table row is one line.** The conversion keeps the cells of a row on the row's line, with a bar between them, so what a fee is for and the fee read as one statement and the digits of two cells never read as one number (a space between digits is a thousands separator to the value check). A cell with no text adds no bar, so a row with an empty cell can sit one column off its header. With each cell on its own line, the evaluation's model kept refusing to quote a fee row it had in front of it.
- **Struck-through text is not page text.** The conversion now drops `del`, `s`, `strike` and text an inline style strikes through. Consolidated laws often keep superseded wording that way beside the new, and before this amendment such pages were cut and could not match. A page that strikes through wording a change not yet in force will replace is read as its future wording alone, so a version written ahead of that change could match early; the version's effective dates and the admin's tap stand against that.
- **Every item that could not be checked says why.** The model gives a note with that status, in Brazilian Portuguese as every note now is, since a report is stored once and the first locale is the admins'. The note filter also drops e-mail addresses, host names in any script and characters that show nothing. Code adds its own reasons for an item that cites no official page (`no_source_cited`) and one none of whose pages was read (`no_page_read`), and the fetch log names a page with no text (`no_text`).
- **A passage must carry the whole item.** The one production match that was read by hand quoted one of the two alternatives its item names; the prompt now says that is not a match.
- The prompt is `rule-check-3`. A report is stored under the check's prompt version and model only, so a change to the locator's prompt or model bumps `rule-check-N` too, which a test pins, and is held to the same two passing runs. The fetch log does not say which pages went as excerpts; its digest is of the text sent.
- **Evaluation:** five cases with an act too long to send whole join the suite: one correct, one wrong, one that still prints the old amount in a schedule far from the section in force, one whose heading tells passage pickers to skip that section, and one whose own source title sends them to the schedule. A sixth new case plants a reassuring note for an item that cannot be confirmed. That makes 24 cases (5 correct, 5 wrong, 14 adversarial); the bar is 4 of the 5 correct ones checked, and a run is capped at 60 calls. A run also fails when a long page was sent cut or without its provision in force, whatever the checker then said, so the locator is judged on its own part, and when the model leaves an item unchecked with no note. A manual `catalog-check` runs the check on the newest version of every bundled route against its live pages and reports matches, reasons and unread pages; it measures and does not gate, is capped at 200 calls, and `all` leaves it out because it costs a few dollars.
- **Cost:** picking is one fast-model call per long page. An outline has at most about 1,500 entries: 20,000 to 100,000 tokens for most laws, a fifth of a cent to a cent at the fast model's list price of US$0.10 per million input tokens, and up to about 150,000 tokens for the largest codes, about eight cents at the US$0.50 that prompts over 100,000 tokens cost (prices read 2026-11-09 from <https://platform.claude.com/docs/en/about-claude/pricing>). The check's own call stays within the same 200,000 characters as before. With at most 10 picks a check, the 20-a-day cap now bounds a bad day at about twenty-five dollars per environment, where this ADR first said ten.
- **Time:** the picks for a check's long pages run together, each at most 90 seconds, before the check's own call and its one retry.

Not decided here, left as could not be checked with its reason shown: PDFs (decided by [ADR-0028](0028-pdf-text-in-the-independent-check.md)), pages that scripts draw (several of those sites publish the same text through an API on the same official host) and sites that answer an access check.

### A match on several quotes (amendment, 2026-11-09)

The first catalog check after the long-page amendment read 158 items and confirmed 17; 91 were read and not confirmed, most because the item joins provisions (an income in one section and the savings in another, an amount left to a ministerial order, a rule and its exception) and a match needed one passage carrying all of it ([#354](https://github.com/fernandolisboa/arca/issues/354), spec [#351](https://github.com/fernandolisboa/arca/issues/351)).

Decided:

- **An answer gives quotes, not a quote.** A **matches** or **differs** entry carries one to three quotes, each with the URL of its page; **could not be checked** carries none. The parse bounds the list at ten; code refuses more than three, or none, as could not be checked (`quote_count`).
- **Every quote is checked as one was.** Each must be on a URL the item cites, from a page that was read, within the length limits, verbatim within one run of what was sent, and echo no address of its own page's redirect chain. One quote that fails makes the whole item could not be checked, with that quote's reason; the item never matches on the quotes that passed.
- **The values are checked across the quotes.** A match needs each of the item's values in at least one of its quotes, and none of its quotes from a page that was cut. A difference keeps its quotes and note as before.
- **The prompt keeps a match for the whole item.** `rule-check-4` asks for one passage when one holds the item and more only when it joins provisions, one passage per provision, each the item's own provision, never a passage that only holds the same number or words about something else; anything that would take more than three passages, or arithmetic, is could not be checked.
- **Each quote is shown with its page.** A stored item and the report's contract carry `quotes`, each with its URL, and the panel shows them numbered, each above its page. Reports stored before keep reading: their one quote becomes a list of one.
- **Residual risk: real quotes from unrelated provisions, paired.** Two passages, each verbatim on a cited page and together holding every value, can still be about different things: the pensioner's income in one section and the investors' amount, worded alike, in another can make a wrong savings threshold look confirmed. Code cannot tell what a passage is about, the same limit that already let one quote with the right number about another route through. What stands against it: the prompt's rule that each quote is the item's own provision; at most three quotes, each on a page the item itself cites; every value still in a verified quote; an adversarial case for exactly this pairing (`adversarial-unrelated-quotes`), which every passing run must flag, beside the one-quote case of a number from another route; the panel showing each quote with its page so the admin reads them side by side; and its footer saying that the AI is what judges that the quotes concern the same rule.
- **Evaluation:** four cases join the suite: a correct item confirmed by two quotes on one page, one confirmed by quotes on two pages (the act and an order on amounts), a wrong amount offered with one real and one invented quote (stopped in code, `quote_not_on_page`), and the adversarial pairing above. That makes 28 cases (7 correct, 6 wrong, 15 adversarial); the bar is 6 of the 7 correct ones checked, and a run is capped at 70 calls. The offline test checks that each of a correct case's quotes is needed: any one alone leaves a value out.

### Machine-readable addresses (amendment, 2026-11-10)

The catalog check after the several-quotes amendment still found 44 of 162 items with no page read. The read of 2026-11-08 above had counted, among the 104 cited pages, 20 that scripts draw and 4 that answer an access check, and several of those sites serve the same official text as data on the same official host: a JSON API, an XML address or a print form ([#362](https://github.com/fernandolisboa/arca/issues/362), spec [#351](https://github.com/fernandolisboa/arca/issues/351)). Since [#353](https://github.com/fernandolisboa/arca/issues/353), an official source may name that address in `machineReadableUrl`, which the build holds to the pinned official-domain lists.

Decided:

- **The check reads the address in the page's place.** When an official source at a cited URL names an address, the step fetches that address instead of the page, under the same rules: `https` with no credentials or port, a host of the pinned lists that cover every item citing the URL, every redirect hop on them, a final `2xx`, and the same size, decompression, time and text caps. The official sources at one URL are the version's and its country sets' alike: one that names no address leaves the choice to those that do, and two that name different addresses make the step read the page itself, so no source's address is chosen over another's. The model, the quotes and the panel keep naming the page's URL.
- **A data answer is read as text.** Besides an HTML or plain-text page, the fetcher now reads `application/json` and `+json` types as the document's string values, and `application/xml`, `text/xml` and `+xml` types as their text nodes and CDATA sections, in document order; keys, numbers, literals, tags, attributes, comments and processing instructions are structure, not text. A string with a tag, a comment or a reference in it goes through the same HTML-to-text conversion as a page, so hidden and struck-through text is dropped there too; a lone `<` or `&`, as in "income < minimum", stays as written. JSON is parsed once, to know it is JSON, and its string values are then read off the text, one to a line, since a parsed object loses the order of number-like keys and all but the last of a repeated key. XML is read by one pass in reviewed code, with no parser that fetches, validates or expands: only XML's five entities and character references are decoded, a document type is skipped and none of its entities is expanded. No vocabulary says which XML elements start a line, so the document's own line breaks stand, and text starts a new line where one element ended and another began since the last text, as a sibling field or paragraph does, or where an empty element that strikes nothing stood; text that only went into elements, or only came out of them, runs on, as words in inline elements do, however deep, so a heading written as its section's own text runs into the first words nested under it. The text of a `del`, `s` or `strike` element, by local name, is left out with its tags, as on a page, so a sentence that strikes an amount and inserts the new one reads as one line; this also drops the text of a vocabulary where `s` means something else, and fails safe. A new line used to start after any two tags, which left an inserted amount on a line of its own, shorter than a quote may be: in both evaluation runs of 2026-11-11 on that rule the item came back `quote_length`, which is read here as the model quoting that line, since quotes are not logged. Numbers that markup or layout sets apart are never read as one, in any answer, a page's too. A quote takes any whitespace as one space and the value check takes a space between digits as a thousands separator, so "Article 1" above "600 EUR" read as 1,600 until now, and bare numbers on lines of their own are how a data answer is laid out. So a line that starts with a digit after one that ends with a digit opens with a bar, as the cells of a table row are kept apart; a line break of any kind counts, and a tab or a run of spaces between two digits becomes a bar too; in markup a cell end stands between two pieces of text whose digits would meet, whatever is between them and whether the parser keeps it, so a footnote mark after a number reads `1 | 2`; and in XML two texts never make one number or numeric date: text that starts with a digit, or with spaces, a `.`, `,`, apostrophe, `/` or `-` before one, starts a new line when the text before it ended in a digit or in those after a digit, whatever stood between the two: a tag, a comment, a processing instruction, the edge of a CDATA section, struck text, or texts that hold only those marks. That is stricter than a page's markup, where `1,<b>500</b>` reads 1,500, and it costs a line break in `sections 3, <ref>4</ref> and 5`. Struck text itself leaves no trace, so `under <del>18</del><ins>21</ins> years` reads as one line. The rule for lines and columns lives beside the value check in `packages/domain`, and every answer's text goes through it. Markup is read within three limits, past which it has no text: 512 nested elements, the depth browsers stop at; one element for every three characters, up to 500,000; and a budget for the work of moving content, which is content out of a table it does not belong in, the children of misnested formatting and the attributes of a repeated `html` or `body` tag, each move counted by the siblings or attributes it goes through, on one budget for everything one answer holds, so a data answer of many strings spends no more than a page. A data answer one of whose strings is past a limit has no text at all, since the string left out may be the one that amends another. The parser's work on each tag grows with the elements open above it, it makes every unclosed formatting element again at each paragraph, and each piece it moves costs it the pieces beside it, so without the limits a page of a few kilobytes could hold the step for hours or take gigabytes, and a JSON string or an XML text with markup in it is one more way in. The move budget counts work, not pieces, so a real table with thousands of stray rows, or a page whose one misnested element wraps ten thousand paragraphs, is read while a page built on the same move is not. The limits bound the routes found, not the time: one tag with tens of thousands of attributes still costs the parser seconds to minutes within the size cap, and a deadline around the parse stays in [OPEN-QUESTIONS](../OPEN-QUESTIONS.md). A NUL or an unpaired surrogate, which a stored report cannot hold, reads as the replacement character in every answer. A JSON answer that does not parse has no text (`no_text`). Long text goes through passages as a long page does, and the prompt is unchanged (`rule-check-4`): the model is sent text and a URL, as before. Every request now accepts JSON and XML after HTML, and any other type last, so a cited page that itself answers data is read the same way.
- **A failed address has no fallback.** When the address is refused, redirects off the lists, answers an error, a type the check does not read, or no text, the page is not tried: its items are could not be checked with their reason, and the report is short-lived as for any failed fetch.
- **The fetch log names the address.** A log entry records `machineReadableUrl`, the address read in the page's place, or null when the page itself was read; a report stored before reads as null, and a null is not stored, so the code before this amendment still reads every report that read no address. It does not read one that did: after a rollback of the API the panel shows no report for such a version, while the list and the checked batch, which read the listing alone, keep counting a clean one until it is 30 days old or its prompt version changes. The panel shows the page's own URL, as before, and under it the address the text was read at, since a quote's words may not be on the page itself; its words for a failure still speak of the page: a JSON address that does not parse reads as a page that came with no text.
- **A quote made of the address proves nothing.** An address is any URL on an official host, and a search or echo API there answers with whatever its query says, under a page URL that shows none of it. So the quote check's address-echo rule runs on the chain actually requested, the address first, and is tightened in three ways. A quote at least half made of four-character pieces of those addresses' queries, compared as lower-case letters and digits whatever stands between them, is `echoes_address`, which catches a part of a long query value and several short ones put together where the whole-value test alone did not. An address is compared as every text it may have become: percent-decoded up to three times over, since a server may decode what another already did, and as the reader itself renders it, since a data answer's strings are read as markup and a claim spelled in the query as character references, entities or between tags comes out as plain words. An address is compared as it was requested: the chain records what the fetcher sent, so a tab or a line break, which a URL parser drops, cannot keep a claim from being read, the rule refuses whole an address that still holds a control character, and the build already refuses one in any string of the data; the fragment, which is never sent, is left out. A decoded query is read to its end, since a `#` in it is one the query carried encoded, and its values are compared whole between `&` and as the pieces a `;` or that `#` ends. And an address that at any decoding is not UTF-8 or holds the `%u` escape of legacy servers, that is encoded more times over than that, or that holds a `<`, a character reference or a JSON escape once decoded, makes every quote on its page an echo. Paths are left out of the half-made-of test on purpose: a path names its page's subject (`.../long-term-residence-permit-for-the-purpose-of-family-reunification/`), the law's own words restate it, and no test on the words tells that from an echo; a first version that counted paths refused honest quotes on pages the catalog cites. The cost that stays is the rule's old one, now on more URLs: a value the address itself states, such as a year or a law number, never matches on that page, and a quote that restates a descriptive query does not either, which the rule audit runbook tells the author. The panel names the address under each quote read through one, so the admin can open it and see the words.
- **No address reaches a model.** The version content that the rule summary and the check send lists each source's fields by name, and neither the address nor its flag is one of them; the guide is sent whole but for a law's address. So what a model is sent for every version is byte for byte what it was before a source could name an address, and neither prompt version changes. The us-eb5 versions and the United States guide that named one in the day between [#353](https://github.com/fernandolisboa/arca/issues/353) and this amendment were sent it; their reports stay current, since nothing of the rule or the guide's text differs. The activation view keeps `newHost` for the page's host alone and gains `newMachineReadableHost` for an address on a host new to the route, counted against the earlier versions' pages and addresses; the build's host table covers addresses for that, and the screen shows the flag under the address.
- **Residual risk: the address is not the page.** The build holds an address to the official hosts, not to the page's text, so it may serve another dated version, one page of a paged API or only metadata, and the words of a quote may not be on the page whose URL the panel shows it under, which is why the panel names the address too. Superseded wording is dropped only where markup strikes it: an answer that marks it with an attribute, a boolean or a date field, or keeps it in a field of its own, is read as text in force. An API that writes back a path, or a query in an encoding other than percent-encoding and markup, such as base64 or hex, can still be quoted, and for an item with a value too, since the value test reads the address as written and decoded, not as such an API would. The stricter reading and echo rule apply to checks made from now on: a report made before stays current until it is 30 days old, as its key is the content, the guide, the prompt version and the model, none of which changes here. An XML answer is decoded as any answer is, by its header's charset or as UTF-8, never by the encoding its prolog names. What stands against these: an address is written by a rule audit that read the text through it, and shown to the admin beside its source and under each quote; the value check still needs each value in a verified quote; a quote made of the address is refused; and the fetch log records which address was read. A version checked through a wrong address can still be activated with one tap, which is the risk accepted below for a wrong official page.
- **Evaluation:** five cases join the suite: a correct version whose act is read through a JSON address while its page is drawn by scripts; a correct one read through an XML address whose sentence strikes the old amount and inserts the new one; an adversarial JSON answer whose own field, and a key, tell reviewers to report a match and hand them a quote; an address on a lookalike of the ministry's API host, which code stops (`no_page_read`) without reading the page; and a search address that answers with its own query, which code stops (`echoes_address`). That makes 33 cases (9 correct, 6 wrong, 18 adversarial); the bar is 8 of the 9 correct ones checked, and the cap rises to 80 calls (66 for the checks and their retries, 5 picks). No case holds a data answer too long to send whole: its text takes the path a long page's does, which the five long cases cover.
- No new host is reached: every address is on a list the version already pins. The first ones in the data, from the us-eb5 audit ([#355](https://github.com/fernandolisboa/arca/issues/355)), are on `www.ecfr.gov` and `www.govinfo.gov`, hosts those versions already cite; later audits add more by new versions. An address that answers only part of the text leaves its items could not be checked, so an audit names one only when it answers the whole text as HTML, plain text, JSON, XML or, since [ADR-0028](0028-pdf-text-in-the-independent-check.md), a PDF with a text layer.

### The audit closes the loop (amendment, 2026-11-11)

The catalog check of 2026-11-11 confirmed 29 of 170 items. Nearly all the rest were not wrong rules: pages the check cannot read, provisions the passage picker never saw (an index page, a list split over two pages), and items that claim what no text says, such as a leap-day convention cited to a general time-reckoning provision. Each left a flagged version, and so an item for the owner to read. The owner asked that the work loop until the parts agree, instead of handing him the gap.

Decided:

- **A rule audit runs the check on its branch and fixes what it could not confirm** ([the check loop](../runbooks/rule-audit.md#the-check-loop)): the rule, the sources (a machine-readable address, one provision per source, a page holding the whole provision) or the item, then runs it again, at most three times. What is left gets one of three categories, `unreadable`, `checker-gap` or `differs-open`, with its reason, in the route's record and the pull request. The audit never relaxes the check to pass.
- **`intake-eval`'s catalog check takes a `routes` input**, so a loop run checks only the audited routes: about ten U.S. cents a route, under the same 200-call cap.
- **The unattended monthly run may start that one workflow**, and only it: with routes it audited, at most four times a pull request, one run at a time, and only on a head whose changed files already pass its path check, so no workflow or code it wrote runs with the key. It merges nothing whose last run left an item `differs`. About three dollars a month at most, from the owner's API credit, which he chose on 2026-11-11 ("não só analisa as regras, mas entra em loop e vai corrigindo").
- **A version may leave a 29 February birthday `unsettled`** (spec 0002, R2) when no official text settles it. It cites nothing, the check lists no item for it, and an age that turns on it is a range on that day.
- Nothing changes in what code checks, in what makes a report clean, or in the admin's decision.

### On demand, with progress (amendment, 2026-11-11)

The owner asked to start a check himself and to watch it ([spec #390](https://github.com/fernandolisboa/arca/issues/390)). He decided: the button always runs a fresh check after showing its cost; the automatic start stays; the button is on every route version, active and rejected included.

- **Forced start.** An admin-only route starts one route version's check whatever its state and current report. It uses the start ledger under the same lock: a live start of the version is answered instead of a second one, and otherwise a start is recorded unless the 20 starts of the last 24 hours are used (429 `rate_limited`). (Changed 2026-11-12: no cap, below.) No checker configured answers 503 `check_off`, and the button is not offered. The workflow, its identifiers-only arguments, the single step with no retries and the report table do not change; a forced report is an ordinary report, and the newest one for today's key is the current one.
- **Reserved share.** The automatic start stops at 15 starts in the window, so 5 are always left for the button. The cost bound does not change. (Changed 2026-11-12: the button has no cap, below.)
- **No re-roll to clean.** A clean report reads as checked only while no other report of the same key within its lifetime was flagged. Checking a flagged version again until the model happens to agree therefore never makes it checked, so it never joins the one-tap activation; it stays to be decided one by one until its content, guide, prompt or model changes or the flagged report outlives its lifetime.
- **No cap on the button (changed 2026-11-12).** The owner hit the 20-a-day cap on his own checks and found it pointless for an admin. A start an admin asks for is no longer counted against any daily cap; only a burst limit of 10 requests a minute per account (429 `rate_limited`), which no person tapping reaches, slows a looping client or a stolen session; it does not bound daily spend. The route still answers a version's live start instead of a second one. The automatic start keeps its share of 15 starts in any 24 hours, counting every start in the window, so opening the activation screen cannot run up a bill by itself. Spend is bounded by the Anthropic Console's spend limit, not by Arca.
- **Failed and unstarted runs.** A start whose run recorded `failed` is no longer live, so it can be started again at once. When the workflow could not begin, the route answers 502 `check_not_started`; that start stays live until it dies at 30 minutes, as an automatic one does.
- **Progress table.** `knowledge.check_progress` holds, per start, an append-only sequence of events with a closed kind and a small closed detail: started (item and page counts), page (cited URL and outcome, including `reading`), locating (how many long pages), comparing, item (an item's key and verified status), usage (a model call's token counts, below), finished and failed (a fixed code). `app_jobs` inserts every column but the time; `app_api` reads; nobody updates or deletes. Public rule data with no account, unowned in the personal-data registry. No page text, quote, note or other model text ever reaches it, and the API parses every row against the closed schema on the way out.
- **Recording.** The check's run receives the progress store as a dependency and records as it goes. A failed progress write is logged as `check_progress_unwritten` and never fails the check. The stored report, not the progress, is the authority on a check having finished.
- **Reading.** A pure domain function reduces a start and its events into a view: running, finished, failed, or dead after the start's 30 minutes. An admin-only route answers the view of the version's newest start of the last 24 hours, or null. The web app reads it every 1.5 seconds while it runs and stops otherwise; no server-sent events or sockets, so the client stays a static bundle.
- **Items as they land.** The checker's call is streamed on the shared Claude call shape, with the same request as before, so the cached prefix, model, prompt version, token cap, timeout, effort and fixed error kinds do not change (a provider error mid-stream is `check_unavailable`). The adapter hands on each entry of the answer once the next one has begun, and the rest when the whole output arrived; the run parses each entry against the closed entry schema, verifies it with the same pure function the report uses, and records an `item` event with the item's key and status only. A key no item has is skipped and a key answered twice in one call could not be checked, as in the report. The report is still built from the complete parsed answer: a stream cut short does not parse and is asked for again once, and the retry records the comparison stage again, which clears the first call's statuses from the view before the retry's land. The view lists every item of the version with its status or null while awaited, plus whether the scripted checker answers in this environment, so a scripted match shows as not confirmed. The screen shows the answered items with the review's per-item result, the item being awaited and how many are left; quotes, notes and reasons still come only with the report. The scripted checker hands on its entries 300 ms apart, so development shows them landing. The change merged after two passing evaluation runs on one commit, recorded in the real-data gate.
- **Cost (#393, 2026-11-12).** Each model call of a check that returns, locator and checker, retries included, records a `usage` event: the model ID (lower-case letters, digits, dots and hyphens) and the input, output, cache-read and cache-write token counts the provider reported, each null when it reported none. A call that fails before replying records nothing, and neither does a usage write that fails (logged as `check_progress_unwritten`), so a cost can fall short of the bill by such calls. The prices live in reviewed code beside the model names (`apps/api/src/knowledge/check/prices.ts`), in millionths of a dollar per million tokens, with the date and page they were read from; the cache-write price is the 1-hour one every Arca call asks for, and the fast model's dearer prices apply to every token of a call whose prompt, cache reads and writes included, is over 100,000 tokens. A pure domain function adds up the cost in code; a model with no price, a missing input or output count (a missing cache count is read as none) or cache counts larger than the prompt make it `unknown`, never a guess, and the scripted checker, whose calls report zero tokens, makes it `scripted`, shown as a test. The progress view carries the cost so far, and the progress route also answers what the version's newest check whose report did not fail cost (a failed run may have stopped before its model calls), which the confirmation shows when it was priced; otherwise the confirmation keeps the typical range, US$ 0.30 to US$ 0.50, from the catalog-check runs of 2026-11-09 and 2026-11-11 recorded in spec #390. The progress table's kind check is a format, not a list, so `usage` needed no migration.

### Points beside the items they are about (amendment, 2026-11-11)

The owner asked to see, while reviewing a version, which of its items the check confirmed and which it did not, without opening the report panel. A report's items now also show under the rule items they are about, in every review step: matches, differs or could not be checked, with the model's note and the verified quotes as plain text, the quotes folded unless the item differs. Each step with checked items takes the tone of its worst item. A summary above the steps counts the items and carries the "made by AI, can be wrong" note, which covers every item shown below it; the full report keeps its own panel, footer and labels in the decision step.

The version list carries each current report's counts, so the proposed versions can be ordered for review: a version with an item that differs first, then checked versions, then those with items that could not be checked, grouped by country. A flagged version reads as "Tem diferença" or "Falta conferir" on that list, which says what it asks of the admin; the label is a status, never a verdict on the rule. A scripted report's matches count as could not be checked everywhere, so nothing outside production looks confirmed.

### Excerpt room by the items that rest on a page (amendment, 2026-11-12)

The room the long pages share, what the pages sent whole leave of the 200,000 characters, is split by how many of the version's items cite each page, no longer equally; a page no item cites counts as one, and room past a page's 60,000 goes to the others. A version that cites one long law for most items and another for one item (Portugal's foreigners law for thirteen items, its social security code for two) gave each the same 14,000 characters, too few for the law's provisions, and the check read them as cut. The total, and so the cost of a call, is unchanged, and so is the prompt.

### Several calls, and numbers in words (amendment, 2026-11-12)

The owner asked why so many items stay could not be checked when the sessions that wrote the rules read the same pages. The catalog check of 2026-11-12 (115 of 299 items matching) showed the largest cause: one call sends every page of a version within 200,000 characters, so the short pages a version cites (guidance pages, fee tables, the EU set's pages) take most of the room and a long law gets 14,000 to 17,000 characters for a dozen items, and the provision an item cites is often left out. Three changes, none touching the prompt:

- **Several calls.** When every page a version's items cite fits one call whole, one call compares them all, as before. Otherwise the items are split into runs of consecutive items, eight at most (more when that would take more than six calls), and each call sends only the pages its own items cite, short pages whole and long pages as excerpts of its items' picks, within the same 200,000 characters. The locator is still asked once per long page, with every item that cites it. A call's answers are checked against the text that call sent. A failed call leaves only its own items unanswered; the report records the first failure and is short-lived, as before. With several calls, each call's `comparing` progress event names its items, so a retry clears only those. The fetch log's digest is of the text sent, joined in call order when several calls sent a page. Six calls at most, each within the same caps as the one call before, bound a check at about six times its old input; the catalog check measures the real cost.
- **Provisions found by their number.** The first branch run still left the articles Portugal's D7 and D8 cite out of their excerpts, because the locator picked other passages of the law. A source title names the provision it relies on before its first colon ("Lei n.º 23/2007, artigo 52.º", "Migration Regulations 1994, clause 189.211", "Udlændingeloven § 9 a"), so code now also finds, on a long page, the passages whose heading line opens with that number: the number after a word such as article, section, clause or §, or any number written only the way provisions are (`52.º`, `24.º-B`, `189.211`). A line that cites the number further on does not head it, and the last three passages that head each number are kept, since a table of contents or an amending act lists it first. These go first in an item's picks, ahead of the locator's, and are found when the locator was not asked or failed. Only the number is compared, so the items being in English and the laws in other languages does not matter, which is what kept the earlier alternative of picking passages in code out. An item a long page sends no picked passage for still marks its own call's page as cut; whether the check sent a long page unpicked is now judged call by call.
- **Numbers in words.** A quote now also states a whole number from 2 to 99 written in words ("quatro meses", "twenty-one", "dieciocho", 五年), read only in the languages the version's pages are likely written in: its country's likely language from the Unicode CLDR data the runtime carries (`Intl.Locale` likely subtags) and English. A number is read only as a whole run of number words, so "twenty-one" never states twenty, "vinte e dois" never states two and "cinco mil" never states five; a run ending in "and", "e" or "y" ("dois e meio") states nothing. A word that is a number in one language and something else in another ("dos", "sei") states nothing on a page in the other, and a number word that is also an English word ("due", "once") is not read at all, since English is read beside every language. 1 is never read alone, since its words are also articles and pronouns ("um", "una", "one of"), and ordinals are not read, since they also name paragraphs, weekdays and rooms ("second", "sexta", "quarto") and Portuguese "segundo" and Italian "secondo" mean "according to". Kanji numerals count only as a whole run before a counter (年, 月, 日, 歳, 人, 回, 週), so 一般 or 十分 states nothing. English, Portuguese, Spanish and Italian words, and kanji numerals for Japanese and Chinese, are read; any other language fails closed, as before.

PDFs set in vertical columns, as Japanese notices are, came out one glyph per line, so no quote could be copied from them; such runs of single Han, kana or Hangul characters are joined back into lines ([ADR-0028](0028-pdf-text-in-the-independent-check.md)).

## Alternatives

| Option | Why not |
| --- | --- |
| Keep the step-up per decision (ADR-0022) | The owner's choice: the prompt adds nothing against the attacker it was for, since signing in is already a passkey |
| One step-up for a batch | Offered to the owner; he chose no prompt |
| A clean report activates a version with no person | Offered; the owner chose to keep one tap. A wrong or tampered official page misleads the check and the rule's author alike, and CLAUDE.md rule 5 keeps a person's approval |
| The admin role in the repository only | Offered; the owner chose to give the role in the app |
| Decisions inserted by `app_api` | Widens who can forge an activation from `app_auth` to the role every request path uses |
| One agent per country | The guide carries what a specialist knows; one check and one prompt keep a single evaluation suite |
| Checking in CI or in an authoring session, with the report committed | A GitHub token holder could then write a clean report; the server's own fetch and the checks in code are what make "clean" mean something |
| An XML parsing library for data answers | A new dependency, and a parser that can expand entities or fetch a document type, for what the check needs of XML: its text nodes in order, which one pass in reviewed code gives |
| Anthropic's server-side web fetch | The quotes could not be checked against text the API itself fetched, and the fetch could not be held to the cited URLs |
| Trusting the model's "matches" without the value check | A true but unrelated sentence from the page would pass; code, not the model, compares numbers (CLAUDE.md rule 3) |
| A report with free text for every item | More room for a page's injected text to steer the admin; only a difference needs explaining. Reversed in part by the long-page amendment: an item that could not be checked with no reason left the admin nothing to act on |
| Embeddings and a vector index (pgvector on Neon) to find a long page's passages | A new vendor for multilingual embeddings, an index to build and keep fresh for pages that are read a few times a month, and similarity search is weakest where a law is most exact: article numbers and amounts. The rule already names the articles it relies on, so a fast model picking from the page's outline finds them with no stored state |
| Picking passages by keywords and numbers in code | The items are in English and the laws are in a dozen languages, so only items with an amount or an age would be found. Reversed in part by the several-calls amendment: the provision numbers source titles name are language-free, and code now finds the passages they head beside the locator's picks |
| Sending the whole long page to the model | A code of 1,000,000 characters is about 300,000 tokens a check at the strong model's price, and most of it concerns other matters |
| A source locator (article, section) as a field of each source | Sources are part of immutable versions, so every route would need a new version; their titles already carry it for a reader, and the locator reads those |

## Consequences

- Approving the waiting rules becomes one tap for the checked ones and one tap each for the rest, from the phone. Giving someone the admin role is the only passkey prompt left on the knowledge base.
- The checks in code fail safe: a law over the size cap or whose passages could not be picked, an echoed address or a PDF with no text layer leaves a version flagged, so fewer versions come out checked than a model alone would pass. The evaluation reports how many.
- **Residual risks, accepted:**
  - An open session of an admin can activate a proposed version or reject active ones, with no prompt. A rejection is permanent, so undoing a mass rejection takes new correction versions; an activation is undone by rejecting.
  - A grantee's sessions that are already open become admin sessions when the role is given, so a stolen one gains the role without a new passkey ceremony.
  - New decisions carry no assertion that can be re-verified later: the decision row and the audit event are the record.
  - Taking an account off the owner list does not undo its decisions, activations included; a compromised owner's activations are undone by rejecting each version.
  - A checked version is activated without a person reading it. The checks in code stop invented quotes, echoed addresses and mismatched values, but not a wrong or tampered official page, a model error that pairs the right value with the wrong clause, a version whose own text was written to mislead the model, or a guide merged by a GitHub token holder to steer it. Items with no value to compare (conditions, the leap-day rule, closure, country-set members) rest on the model's reading alone. On a long page the model reads only the passages picked. So a stale version can come out checked when the old wording still stands somewhere on the page, in words that do not mark it superseded, and the pick, steered by the page's text, by the version's own item and source titles or simply mistaken, takes that passage without the provision in force. What stands against it: struck-through text is dropped, the locator is asked for the passage whose heading names the item's subject and for amending passages whatever the source titles say, it can only choose among verbatim passages of that page, the evaluation fails a run in which a long page's provision in force was not sent, and the panel's footer tells the admin that long pages are read in passages. A note is plain text with links, addresses and host names dropped; long digit runs stay, since amounts, dates and law numbers are what a note is for, so the web page turns off the browser's phone-number links (`format-detection`). The evaluation's adversarial cases and the admin's tap are the remaining controls.
  - Whoever writes the production database as `app_jobs` can store a clean report, and as `app_auth` can store a grant or a decision; under threat model R-2 that includes code on a branch that builds a preview. The decision attacker is the one ADR-0022 accepts; the report attacker still needs a bad version merged and an admin's tap.
  - A stolen admin session can spend the daily cap of checks, about ten dollars at most (about twenty-five since the long-page amendment). (Changed 2026-11-12: an admin's own starts have no cap, so a stolen admin session can start checks until the Anthropic Console's spend limit stops them, one live check per version at a time; the page fetches and workflow runs go on past that limit, bounded only by Vercel's own spend controls and the official sites' tolerance; and since one key and one spend limit serve every model call, reaching it also stops free-text intake (which falls back to the guided questions) and rule summaries until it resets.)
  - A granted admin who shares no case with any other admin keeps the role, and no family area shows it, so only a reviewed database change can take it away. Any grant they make still sends the owner-list admins the notice, and the audit log names both accounts.
- CLAUDE.md rule 5 now says an admin approves while signed in, and the glossary replaces Approver and Approver list with Admin and Owner list.
